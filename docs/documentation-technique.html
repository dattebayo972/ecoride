2. Architecture du projet

EcoRide adopte un pattern MVC-lite (sans framework) : séparation logique entre vues (pages public/), modèles (src/models/) et helpers (src/helpers/).

2.1 — Pattern de chargement des pages

Chaque page PHP suit le même ordre d'inclusion :

// 1. Session + BASE_URL + helpers
require_once '../src/helpers/auth.php';
require_once '../src/helpers/functions.php';

// 2. Modèles nécessaires (qui incluent db_mysql.php)
require_once '../src/models/CovoiturageModel.php';

// 3. Contrôle d'accès (si page protégée)
requireLogin();
requireRole('chauffeur');

// 4. Traitement POST (formulaires)
if ($_SERVER['REQUEST_METHOD'] === 'POST') { verifyCsrf(); ... }

// 5. Rendu HTML
include '../src/components/header.php';
include '../src/components/navbar.php';
// ... HTML de la page ...
include '../src/components/footer.php';

3.2 — Singleton PDO

function getPDO(): PDO {
    static $pdo = null;
    if ($pdo !== null) return $pdo;

    $pdo = new PDO(
        "mysql:host={$host};dbname={$name};charset=utf8mb4",
        $user, $pass,
        [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES   => false, // Requêtes préparées vraies
        ]
    );
    return $pdo;
}

3.3 — MongoDB — Dual-write avis

À chaque insertion/modification d'avis dans MySQL, un document est synchronisé dans la collection avis de MongoDB Atlas :

// Structure document MongoDB
{
  "_id": ObjectId,
  "avis_id": 42,          // sync avec MySQL
  "covoiturage_id": 12,
  "auteur_pseudo": "marie_d",
  "note": 4,
  "commentaire": "Très bon trajet !",
  "statut": "validé",
  "date_avis": ISODate("2026-05-18")
}

Si la connexion MongoDB échoue, getMongo() retourne null et le code PHP vérifie avant toute écriture (pas d'erreur fatale).

4. Sécurité

OWASP A01
Contrôle d'accès

requireLogin(), requireRole(), requireActive() en tête de chaque page protégée. Vérification systématique que l'utilisateur connecté est propriétaire des ressources qu'il modifie (ex: chauffeur_id = $_SESSION['user_id']).

OWASP A02
Mots de passe

password_hash($mdp, PASSWORD_BCRYPT) à l'inscription. password_verify() à la connexion. Politique forte imposée : ≥ 8 caractères, 1 majuscule, 1 chiffre, 1 spécial. session_regenerate_id(true) après login.

OWASP A03
Injections SQL

100% PDO avec requêtes préparées ($pdo->prepare() + execute([])). PDO::ATTR_EMULATE_PREPARES = false force les vraies requêtes préparées côté serveur MySQL.

OWASP A03
XSS (Cross-Site Scripting)

Toute variable affichée dans le HTML passe par h($var) = htmlspecialchars($str, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8'). Aucune valeur utilisateur affichée sans échappement.

OWASP A05
CSRF

Chaque formulaire POST inclut <?= csrfField() ?>. Le handler vérifie hash_equals(csrfToken(), $_POST['csrf_token']). Token régénéré à chaque session.

OWASP A09
Variables d'environnement

Toutes les credentials (DB_PASS, MONGO_URI, MAIL_PASS) sont dans .env (gitignore). Le fichier .env.example sert de template sans valeurs sensibles.

5. Installation locale (XAMPP)

Cloner le projet

git clone https://github.com/votre-username/ecoride.git "C:/xampp/htdocs/projet_tristan_ecoride/ecoride"

Configurer les variables d'environnement

cp .env.example .env
# Éditer .env :
DB_HOST=localhost
DB_NAME=ecoride
DB_USER=root
DB_PASS=

Créer la base de données dans phpMyAdmin

1. Ouvrir http://localhost/phpmyadmin
2. Créer la base ecoride (charset utf8mb4)
3. Importer sql/create_tables.sql puis sql/seed_data.sql

Lancer XAMPP

Démarrer Apache et MySQL depuis le Control Panel XAMPP.

Accéder à l'application

http://localhost/projet_tristan_ecoride/ecoride/public/

La détection automatique de BASE_URL via SCRIPT_NAME gère le chemin avec espace.

6. Déploiement Heroku

6.1 — Prérequis

  • Compte Heroku (plan Eco ou Basic)
  • Heroku CLI installé : brew install heroku/brew/heroku (Mac) ou installateur Windows
  • Add-on JawsDB MySQL (base de données cloud)

6.2 — Fichiers de déploiement inclus

Procfile

web: vendor/bin/heroku-php-apache2 public/

Indique à Heroku d'utiliser Apache comme serveur web et de servir depuis le dossier public/.

composer.json

{
    "require": { "php": ">=8.1" }
}

Spécifie la version PHP minimale. Heroku installe automatiquement la version correspondante.

6.3 — Procédure de déploiement

Login Heroku

heroku login

Créer l'application

heroku create ecoride-app

Ajouter JawsDB (MySQL cloud)

heroku addons:create jawsdb:kitefin

JawsDB expose automatiquement JAWSDB_URL comme variable d'env.

Configurer les variables d'environnement

heroku config:set DB_HOST=xxxxx.cleardb.net \
    DB_NAME=heroku_xxxxx \
    DB_USER=xxxxx \
    DB_PASS=xxxxx \
    APP_URL=https://ecoride-app.herokuapp.com \
    MAIL_FROM=noreply@ecoride.fr

Pousser le code

git push heroku main

Initialiser la base de données

heroku run php -r "..."
# Ou importer via MySQL Workbench connecté à JawsDB
Note sessions : Heroku peut réinitialiser le système de fichiers à chaque déploiement. Les uploads de photos utilisateurs sont perdus. En production, utiliser un service comme AWS S3 ou Cloudinary pour le stockage des fichiers.

7. Flux de données — Actions clés

7.1 — Recherche de covoiturages

GET /covoiturages.php?depart=Paris&arrivee=Lyon&date=2026-05-20
                     &eco=1&prix_max=20&duree_max=4¬e_min=4

→ CovoiturageModel::search($filters)
  → SELECT cov.*, u.pseudo, u.photo, AVG(a.note) as note_moy
     FROM covoiturage cov
     JOIN utilisateur u ON cov.chauffeur_id = u.utilisateur_id
     LEFT JOIN avis a ON a.covoiturage_id = cov.covoiturage_id AND a.statut = 'valide'
     JOIN voiture v ON cov.voiture_id = v.voiture_id
     WHERE cov.lieu_depart LIKE :dep
       AND cov.lieu_arrivee LIKE :arr
       AND cov.date_depart = :date
       AND cov.statut = 'planifié'
       AND cov.nb_places > 0
       [AND v.energie = 'electrique']  ← si filtre eco
       [AND cov.prix_par_personne <= :prix_max]
       [AND TIMESTAMPDIFF(MINUTE, cov.heure_depart, cov.heure_arrivee) <= :duree_max]
     HAVING [note_moy >= :note_min]
     ORDER BY cov.date_depart, cov.heure_depart

7.2 — Transaction de réservation

try {
    getPDO()->beginTransaction();

    // 1. Insérer la participation
    $stmt = getPDO()->prepare(
        "INSERT INTO participe (covoiturage_id, passager_id, statut, credits_debites)
         VALUES (:cov, :pass, 'reserve', :credits)"
    );

    // 2. Déduire les crédits du passager
    getPDO()->prepare(
        "UPDATE utilisateur SET credits = credits - :prix WHERE utilisateur_id = :id"
    )->execute([...]);

    // 3. Décrémenter les places
    getPDO()->prepare(
        "UPDATE covoiturage SET nb_places = nb_places - 1 WHERE covoiturage_id = :id"
    )->execute([...]);

    getPDO()->commit();
} catch (Exception $e) {
    getPDO()->rollBack();
    setFlash('error', 'Erreur lors de la réservation.');
}
